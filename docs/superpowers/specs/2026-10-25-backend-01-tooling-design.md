# B1 · Tooling, local stack, CI, API doc skeleton — spec

Date: 2026-10-25 · Branch: `chore/b1-tooling` · Status: **awaiting OK** · Version: 0.1.0

## Problem

The repo has only docs. Every later module needs: a local Supabase that resets from migrations in seconds, a test runner for RLS, a linter, CI that proves all of it on every PR, and one place that tells the mobile app what the API is.

## Decisions

1. **Supabase CLI local stack** (`supabase start`, Docker) instead of a bare Postgres container (the `neoteam-social-run` approach). There the remote was the source of truth; here the repo is, so the full stack (Auth, Storage, PostgREST, Studio, Mailpit for emails) runs locally and `supabase db reset` rebuilds it from `supabase/migrations/` + `supabase/seed.sql`.
   - The CLI is a pinned devDependency (`supabase` npm package), so every machine and CI use the same version. The Homebrew install already on Iván's Mac keeps working, but scripts call `pnpm exec supabase`.
2. **pgTAP** via `supabase test db` for every policy and RPC. Tests impersonate users with `set local role authenticated` + `set local request.jwt.claims`; a shared helper file creates test users.
3. **pnpm workspace** at the root with one package today (`admin/`, added in A1). Root scripts drive the database; `admin` scripts drive the panel.
4. **Biome** with the same settings as `neoteam-social-run` (2 spaces, single quotes, no semicolons, `noExplicitAny: error`). SQL is not linted by Biome; SQL style is in `.claude/rules/sql.md`.
5. **CI** (`.github/workflows/ci.yml`) on every PR and push to `main`: install, `pnpm lint`, `supabase start`, `supabase db reset`, `supabase test db`. Admin build joins in A1.
6. **Release workflow** (`.github/workflows/release.yml`), as in `neoteam-social-run`: when `main` gets a commit whose `package.json` version has a matching `## [x.y.z]` section in `CHANGELOG.md`, tag `vx.y.z` and publish a GitHub release with that section.
7. **`docs/api.md` skeleton** with the conventions every module fills in: auth, ids, timestamps, errors, sync rules, and one section per table/RPC added later.

### Conventions written into `docs/api.md` now

- **Ids:** `uuid` v4 generated by the client for every domain row (offline creation). The server never generates ids the app needs to know in advance.
- **Timestamps:** `timestamptz`, UTC on the wire (ISO 8601). `created_at` defaults to `now()`; `updated_at` is set by trigger on every insert and update; the client value is ignored.
- **Soft delete:** domain rows have `deleted_at`; the app sets it, never sends `DELETE`.
- **Errors:** RPCs and triggers raise `P0001` with a Spanish `message` (shown to the user as is) and a stable machine code in `detail` (`not_owner`, `last_owner`, `email_not_confirmed`…). The app branches on `detail`, never on the message text.
- **Unique violations** are not re-raised: Postgres returns `23505` with the constraint name, and `docs/api.md` keeps one table mapping each unique constraint to its detail code (`hives_qr_code_key` → `qr_taken`, `hives_org_name_key` / `apiaries_org_name_key` → `duplicate_name`). Clients map `23505` through that table; an unmapped constraint is a generic "Ya existe un registro igual.". Every unique index is named explicitly so the mapping is stable.
- **Sync pull:** `select * from <table> where updated_at > :cursor order by updated_at, id limit 500`, repeated until a page comes back with fewer than 500 rows. The new cursor is the last row's `updated_at` minus 2 minutes (overlap for transactions that committed late; local upsert by id makes duplicates harmless).
- **Sync push:** `upsert` by `id` (`on conflict (id) do update`), idempotent; the outbox retries with backoff 5 s → 30 s → 2 min → 10 min (cap), and marks the row **requires attention** after a `P0001`/4xx (it will never succeed by retrying).

## Files

`package.json`, `pnpm-workspace.yaml`, `biome.json`, `.gitignore`, `.editorconfig`, `.env.example`, `supabase/config.toml`, `supabase/seed.sql` (empty, filled in later modules), `supabase/tests/_helpers.psql`, `supabase/tests/00_smoke.test.sql`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.claude/rules/sql.md`, `docs/api.md`, `CHANGELOG.md`, `README.md` (Spanish: what the project is and how to run it).

### `supabase/config.toml` settings that matter

- `project_id = "beekeeper"`, Postgres major 17 (match the remote when D1 creates it).
- `[auth]`: `site_url = "http://localhost:5173"`, `additional_redirect_urls = ["landak://"]`, `jwt_expiry = 3600`, refresh token rotation on.
- `[auth.email]`: `enable_signup = true`, `enable_confirmations = true`, `otp_length = 6`, `otp_expiry = 600`, `max_frequency = "60s"`. Email template for OTP in Spanish (`supabase/templates/otp.html`): shows the 6-digit `{{ .Token }}` big, no magic link.
- `[auth.rate_limit]`: `email_sent = 30` locally (Mailpit), remote is set in D1.
- `[storage]` enabled, `file_size_limit = "5MiB"`.
- Mailpit (`[inbucket]`) on 54324 to read sign-in codes locally.

### `.claude/rules/sql.md` (paths: `supabase/**`)

Lowercase SQL, `snake_case`, one migration per change named `<timestamp>_<slug>.sql`, `create … if not exists` never used to hide drift, every table gets RLS enabled in the same migration that creates it, every `security definer` function has `set search_path = ''` and fully-qualified names, every policy calls the `private.*` helpers (B2), every check constraint is named `<table>_<column>_check`.

### `_helpers.psql`

`tests.create_user(email text, confirmed boolean default true) returns uuid` (inserts into `auth.users`, triggers create the profile), `tests.authenticate_as(user_id uuid)` (sets role and claims), `tests.clear_authentication()`. Lives in a `tests` schema created only in the test transaction.

## Security constraints

`.env.example` lists names only: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_DB_PASSWORD` (CLI only, never in an app). `.gitignore` covers `.env*` except `.env.example`, `supabase/.temp`, `supabase/.branches`.

## Out of scope

Any table (B2+), the admin package (A1), the remote project (D1).

## Mobile impact

None in code; `docs/api.md` conventions are what the app's sync engine (mobile M3) implements.
