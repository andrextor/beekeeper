# API contract — Landak Apiario

What the clients (`beekeeper-mobile`, `admin/`) may rely on. Everything here is enforced by the migrations in `supabase/migrations/` and proven by `supabase/tests/`. A breaking change is called out in `CHANGELOG.md` with **BREAKING**.

Clients use `@supabase/supabase-js` with the project URL and the **publishable key** only.

## Conventions

### Ids

`uuid` v4 generated by the client for every domain row, so rows can be created offline. The server never generates an id the app needs to know in advance.

### Timestamps

`timestamptz`, UTC on the wire (ISO 8601). `created_at` defaults to `now()`. `updated_at` is set by a trigger on every insert and update; any client value is ignored.

### Soft delete

Domain rows have `deleted_at`. Clients set it; they never send `DELETE`. Deleted rows still travel through the sync pull, so other devices learn about them.

### Errors

| Source | Shape | Client handling |
|--------|-------|-----------------|
| RPCs and triggers | `code = 'P0001'`, `message` in Spanish (shown as is), `details` = stable machine code | Branch on `details`, never on `message` |
| Unique violations | `code = '23505'`, constraint name in `message` | Map through the table below |
| RLS refusal on insert | `code = '42501'` | Permanent failure ("Requiere atención") |
| Network, 5xx, 429 | — | Retry with backoff |

Unique constraint → detail code (filled in by each module):

| Constraint | Detail code | Message |
|------------|-------------|---------|
| `organization_invites_code_key` | `code_collision` | "No pudimos crear el código. Inténtalo de nuevo." (≈ 1 in 10^12; just retry) |
| `apiaries_org_name_key` | `duplicate_name` | "Ya tienes un apiario con ese nombre." |
| `hives_apiary_name_key` | `duplicate_name` | "Ya hay una colmena con ese nombre en este apiario." |
| `hives_qr_code_key` | `qr_taken` | "Ese código QR ya está en uso en otra colmena." (the app regenerates silently on create; on re-labelling it shows the message) |

A check violation (`23514`, constraint name in `message`) means the client sent a value outside the documented ranges; clients validate the same rules first, so it is shown as "Revisa los datos: hay un valor fuera de rango." and logged.

### Writes refused by RLS

- `insert` / `upsert` that RLS refuses → `42501` ("new row violates row-level security policy"). Permanent.
- A plain `update` / `PATCH` whose row RLS hides or does not let you change returns **200 with an empty body** (`[]` with `Prefer: return=representation`), not an error. Clients that patch must ask for the representation and treat an empty array as refused. The sync engine always pushes with `upsert` by `id`, which fails loudly instead.

### Domain errors raised by triggers

| `details` | Message | When |
|-----------|---------|------|
| `parent_mismatch` | "El registro relacionado no existe, fue eliminado o es de otra organización." | A child points at a parent of another organization or a soft-deleted one, including restoring (`deleted_at = null`) a child whose parent is deleted |
| `immutable_column` | "Un registro no puede cambiar de organización." | An update changes `organization_id` |
| `immutable_column` | "Un registro no puede cambiar de colmena." | An update changes `inspections.hive_id` or `photos.hive_id` (delete it and record it again on the right hive) |
| `missing_author` | "Falta el autor del registro." | Server-side insert without `created_by` (never from clients) |
| `apiary_not_empty` | "El apiario todavía tiene colmenas. Muévelas o elimínalas primero." | Soft-deleting an apiary with any non-deleted hive (dead ones included) |
| `future_date` | "La fecha no puede ser futura." | `hives.colony_started_on`, `inspections.inspected_at` or `hive_events.occurred_at` more than one day ahead |
| `not_member` | "La persona que revisó no pertenece a esta organización." | `inspections.inspected_by` set to (or changed to) someone outside the organization |

An unmapped `23505` is shown as "Ya existe un registro igual.".

### Sync pull

Per table:

```sql
select * from <table>
where updated_at > :cursor
order by updated_at, id
limit 500
```

Repeat until a page returns fewer than 500 rows. The new cursor is the last row's `updated_at` **minus 2 minutes**: the overlap catches transactions that committed late, and local upserts by id make duplicates harmless.

### Sync push

`upsert` by `id` (`on conflict (id) do update`), which is idempotent: a retried request writes the same row. The outbox retries with backoff 5 s → 30 s → 2 min → 10 min (cap). A `P0001`, `23505`, `42501` or other 4xx marks the entry **Requiere atención**; retrying would never succeed.

## Auth

Email + password. **No email is ever sent** (no domain yet): confirmation is off, there are no codes by email and no self-service recovery.

| Step | Call | Notes |
|------|------|-------|
| Sign up | `auth.signUp({ email, password })` | Returns a session at once. Password ≥ 8 characters |
| Sign in | `auth.signInWithPassword({ email, password })` | |
| Sign out | `auth.signOut()` | Clients also wipe local data |
| Forgot password | — | Show "Pide a tu administrador que restablezca tu contraseña." Iván runs `scripts/reset-password.sh <email>` |

Auth errors come in English; clients map `error_code` to Spanish:

| `error_code` | Message |
|--------------|---------|
| `invalid_credentials` | "Correo o contraseña incorrectos." |
| `user_already_exists` / `email_exists` | "Ya existe una cuenta con ese correo. Ingresa con tu contraseña." |
| `weak_password` | "La contraseña debe tener al menos 8 caracteres." |

| `over_request_rate_limit` | "Demasiados intentos. Espera un minuto." |
| network error | "No hay conexión. Revisa tu internet e inténtalo de nuevo." |

After signing in: `rpc('my_memberships')`. No memberships → onboarding offers **Crear mi apiario** (`create_organization`) or **Tengo un código** (`accept_invite`).

### Platform admin

`profiles.is_platform_admin` is set only by SQL: `update public.profiles set is_platform_admin = true where email = '…';`. It reads every organization and writes nothing.

### QR

The printed label encodes `landak://h/<qr_code>` and nothing else. Lookup: local SQLite first; online `from('hives').select(…).eq('qr_code', code)`. An empty result means "not in your organizations": a read never tells another organization's hive from an unknown code. (Creating a hive with a code another organization uses fails with `qr_taken`, which reveals only that the code exists somewhere — it is already printed on that physical label, and no data is exposed.) Re-labelling is an owner update of `qr_code` plus a `qr_relabel` event (B4).

**Who writes:** owners and reviewers insert; owners edit or soft-delete any inspection, reviewers only those they created (others' rows come back as `[]` on PATCH, `42501` on upsert). Soft-deleting an inspection soft-deletes its linked events and photos in the same write (they come back in the next pull with a new `updated_at`); restoring the inspection does not restore them.

### Open tasks

View `hive_open_tasks` (RLS applies): one row per non-deleted hive that has an inspection, with `hive_id`, `organization_id`, `planned_actions`, `inspected_at` of its **latest** non-deleted inspection (ties: highest `id`). "Colmenas por alimentar": `select=hive_id&planned_actions=cs.{feed}`. Older inspections' actions are history, not open tasks.

## Hive timeline

`rpc('hive_timeline', { p_hive_id, p_before?, p_before_id?, p_limit? })` → rows `{ kind: 'inspection' | 'event', id, at, created_by, author_name, data }`, non-deleted only, newest first (`at desc, id desc`). `data` is the full row as JSON, same columns as the tables. `p_limit` defaults to 30, clamped to 1..100. Next page: pass the last item's `at` and `id` as `p_before` / `p_before_id` (an event recorded during an inspection often shares its timestamp). `p_before` alone means strictly before that instant. Runs under RLS: a hive you cannot read returns no rows. `author_name` is `null` when the author's profile is not visible (a member who left).

## Photos

Private bucket `hive-photos` (5 MB per file, `image/jpeg` only) plus table `photos`.

### Files

Two files per photo, made on the phone (the free plan has no image transformations):

| File | Path | Size |
|------|------|------|
| Main | `{organization_id}/{hive_id}/{photo_id}.jpg` | long side 1600 px, JPEG q≈0.7, ~250 KB |
| Thumbnail | `{organization_id}/{hive_id}/{photo_id}.thumb.jpg` | long side 320 px, ~20 KB |

Ids are lowercase uuids. Any other name is refused (`403` from Storage). Members upload only into a non-deleted hive of their organization; the platform admin only reads. Files are never deleted by the app (no delete policy). Retries upload with `upsert: true`, which overwrites the uploader's own file at the same path.

### Upload order

1. Main file → 2. thumbnail → 3. upsert the `photos` row. The row is written last, so a crash leaves at most an orphan file, never a row pointing at nothing. Orphan cleanup is a later job.

Once the row exists the files cannot be replaced (Storage answers `403` to an upsert): a photo is history. **Permanent failures**, shown as "Requiere atención" and never retried: Storage `403` (the hive was deleted or the user left the organization while the photo was queued) and `parent_mismatch` on the row. Network errors, `5xx` and `429` are retried with backoff.

Deleting a hive keeps its history: its inspections, events and photos stay as they are, and clients hide the children of a deleted hive.

### Table `photos`

Common columns plus:

| Column | Type | Rule |
|--------|------|------|
| `hive_id` | uuid | a hive of the same organization, not deleted; cannot change (`immutable_column`) |
| `inspection_id` | uuid | optional; an inspection of the same hive, not deleted (`parent_mismatch`) |
| `storage_path` | text | exactly `{organization_id}/{hive_id}/{id}.jpg` (`23514` on `photos_storage_path_check`) |
| `taken_at` | timestamptz | ≤ now + 1 day (`future_date`) |
| `width`, `height` | integer | 1..10000 |
| `bytes` | integer | 1..5242880, size of the main file |
| `caption` | text | ≤ 300 |

Same write rules as inspections: members insert, the owner edits any, a reviewer only their own; soft delete keeps the files.

### Reading

`storage.from('hive-photos').createSignedUrls(paths, 3600)`: one request per screen (up to 100 paths), thumbnails first. The thumbnail path is `storage_path` with `.jpg` → `.thumb.jpg`; if it returns 400/404, fall back to the main file. No public URLs.

### Free-tier budget

~270 KB per photo → ~3,700 photos in the free 1 GB of storage. Grids load only thumbnails to keep egress low. Past ~700 MB, photos move to Cloudflare R2 behind an Edge Function (new spec); paths and the app's queue stay the same.

## Admin

Read-only RPCs for the platform admin panel. All run under RLS (`security invoker`) and refuse anyone without `profiles.is_platform_admin`: `P0001`, `not_platform_admin`, "Solo administradores de la plataforma.". Counts skip soft-deleted rows and the inspections and events of deleted hives (their history is kept, and clients hide it). Searches are trimmed, cut at 80 characters, case-insensitive, and treat `%` and `_` literally. `p_limit` is clamped to 1..100; pages by `p_offset`.

| RPC | Returns |
|-----|---------|
| `admin_stats()` | `{ organizations, users, apiaries, hives_active, hives_total, inspections_30d, events_30d, photos, storage_bytes, reviewers }`, counting only live organizations (`users` counts everyone) — `storage_bytes` is everything in `hive-photos` (main files, thumbnails, orphans), the number the free tier counts |
| `admin_list_organizations(p_search?, p_limit = 25, p_offset = 0)` | rows `{ id, name, deleted_at, owner_emails, members, apiaries, hives_active, inspections_30d, last_inspection_at, created_at, total_count }`, most recently inspected first; `p_search` matches the name or an owner's email; soft-deleted organizations are listed with `deleted_at` |
| `admin_organization_summary(p_organization_id)` | `{ organization: { id, name, created_at, deleted_at }, members: [{ user_id, email, display_name, role, joined_at }], pending_invites: [{ id, label, role, created_at, expires_at }], apiaries: [{ id, name, hives_active, hives_total, last_inspection_at }] }`, or `null` if it does not exist |
| `admin_list_users(p_search?, p_limit = 25, p_offset = 0)` | rows `{ id, email, display_name, is_platform_admin, organizations: [{ id, name, role, deleted_at }], created_at, total_count }`, newest first; `p_search` matches email or display name |

Apiary → hive → timeline screens use plain selects under RLS (`hives?apiary_id=eq.…`) and `hive_timeline`.
